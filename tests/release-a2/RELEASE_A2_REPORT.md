## 結論

Release A2の対象だった #10「ファイル境界」、#11「IPC境界」、#18「本番デモAPIフォールバック」を修正した。専用テスト14件、Release A1回帰15件、Phase 0 harness 4件、設定チェックに成功した。

既知不具合台帳ではT01・T02・T09が通常成功し、今回の対象外であるT03〜T08・T10〜T15の12件はTODOとして残している。通常失敗は0件である。

## 実装内容

### 1. ファイル境界

- 相対画像パス正規化、許可拡張子、通常ファイル、画像署名、realpath境界、SHA-256を`shared/asset-validation.js`へ集約した。
- runtime resolverは、外部シンボリックリンク、ディレクトリ、禁止拡張子、拡張子と内容の不一致、デコード不能画像を拒否する。
- 素材ルート自体がシンボリックリンクの場合も、旧素材移行より前に起動を停止する。
- 通常画像取込は、source検証 → 一時コピー → コピー後再検証 → SHA-256一致 → renameの順で確定する。
- 透明PNG保存は、一時PNGへ書込 → 署名確認 → Electronデコード確認 → SHA-256一致 → renameの順で確定する。
- 失敗時は一時ファイルを削除し、最終ファイルや既存画像を残したままにする。
- Release A1の配布トランザクションも同じ共通検証へ接続した。

### 2. IPC・preload境界

- IPC送信元について、期待BrowserWindow、`senderFrame === sender.mainFrame`、完全な`file:` URLを確認する。
- 共通読取は設定画面とマスコット画面だけに限定した。
- 設定変更系IPCは設定画面のトップフレームだけに限定した。
- マウス透過・反映結果IPCはマスコット画面のトップフレームだけに限定した。
- 不明なIPC権限分類は許可側へ流さず、明示的に拒否する。
- 設定用`preload.js`からマスコット専用APIを削除した。
- `preload-mascot.js`を新設し、runtimeに必要な5機能だけを公開した。
- 新preloadを`build.files`へ追加した。

### 3. BrowserWindow境界

- 設定画面とマスコット画面の両方で`sandbox: true`を有効化した。
- 新規ウィンドウを拒否した。
- 期待するローカルHTML以外へのnavigationを拒否した。
- webviewの付与を拒否した。

### 4. 設定画面のAPI欠落

- `window.mascotAPI`不在時に成功デモAPIを生成する処理を削除した。
- 必要な9メソッドが揃わない場合は、設定読込・編集・画像取込・保存・再読込・配布反映を無効化する。
- API不在時は「保存済み」「反映済み」を表示せず、デスクトップアプリの再起動を案内する。
